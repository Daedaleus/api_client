# Collection file format, version 1

A collection is a folder of plain [TOML](https://toml.io) files, made to be
read, edited and merged in git. One file per request; folders of the
collection are real folders.

```
shop-api/                    ← collection root
  collection.toml            ← collection settings and order of the top level
  auth/                      ← a folder of the collection
    folder.toml              ← folder settings and order (optional)
    login.toml               ← a request
  products/
    folder.toml
    list-products.toml
    get-product.toml
```

## Common rules

- Encoding UTF-8, any line endings.
- Every file starts with `format` and `version`. A reader refuses a file
  whose `format` does not match its role.
- **Versions.** A reader migrates older versions in memory and writes the
  file only when the user saves it, so opening a collection never changes
  files. A file with a **newer** version than the program knows is shown
  read-only and never written.
- **Damaged files** (not valid TOML, wrong `format`, missing fields) are
  reported and left untouched; the rest of the collection still opens.
- **Comments and key order** in a file survive saving: only changed values
  are rewritten.
- **IDs** are UUIDs (version 7) stored in the file. They stay the same when a
  file is renamed or moved, so references (history, open tabs) survive.
- **Unknown keys** are kept when saving, so newer or other tools can add
  data without it getting lost.
- Names starting with `.`, and the folders `environments` and `secrets` in the
  collection root (used from milestone M3), are not part of the request tree.

## `collection.toml`

```toml
format = "api-client/collection"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a70"
name = "Shop API"
order = ["auth", "products"]
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the collection |
| `name` | string | Display name |
| `order` | array of strings, optional | File and folder names of the top level in display order |
| `variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`): variables for every request of the collection |

## `folder.toml`

```toml
format = "api-client/folder"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a71"
name = "Products"
order = ["list-products.toml", "get-product.toml"]
```

Same keys as `collection.toml` (including `variables`, which apply to the
requests in the folder and its subfolders). The file is optional: without
it, the folder is named after its directory and gets an ID when it is first
saved.

**Order.** Entries listed in `order` come first, in that order; entries that
exist but are not listed (added by hand or by a git merge) follow,
sorted by name; listed entries that do not exist are skipped. Nothing is
hidden because of a stale `order`.

## Request files (`*.toml`)

Every other `.toml` file in the collection is a request.

```toml
format = "api-client/request"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a77"
name = "Get product"

[request]
method = "GET"
url = "{{baseUrl}}/products/42"

[[request.headers]]
name = "Accept"
value = "application/json"
enabled = true

[request.body]
type = "json"
content = '''
{ "name": "Teapot" }
'''
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the request |
| `name` | string | Display name |
| `request.method` | string | HTTP method (case-sensitive token, e.g. `GET`, `PROPFIND`) |
| `request.url` | string | URL; may contain `{{variables}}` (resolved from milestone M3) |
| `request.headers` | array of tables, optional | `name`, `value`, `enabled` (default `true`) |
| `request.body` | table, optional | `type` = `"json"` or `"text"`, `content` = string; missing = no body |
| `request.variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`): variables of this request only |

Further body types (form, multipart, binary) and auth follow in milestone M5
as new keys; files without them stay valid.

**File names** are derived from the name when a request is created
(lower case, `-` instead of spaces, umlauts transliterated, unique in the
folder). Renaming a request later does not rename its file automatically.

## Environment files (`environments/*.toml`)

Every `.toml` file in the `environments` folder of the collection root is an
environment: a named set of variables for `{{name}}` placeholders.

```toml
format = "api-client/environment"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a80"
name = "Staging"

[[variables]]
name = "baseUrl"
value = "https://staging.example.com"

[[variables]]
name = "debug"
value = "1"
enabled = false

[[variables]]
name = "token"
secret = true
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the environment |
| `name` | string | Display name (default: file name) |
| `variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`), `secret` (default `false`) |

**Placeholders.** Before a request is sent, every `{{name}}` in its URL,
header names and values and body is replaced by the value of the enabled
variable `name`. Variables can be defined in several places; from weakest
to strongest:

1. the collection (`collection.toml`),
2. the chosen environment,
3. the folders around the request (`folder.toml`), outer to inner,
4. the request itself (`request.variables`).

The stronger place wins. (Variables set by scripts at run time will rank
above all of them, milestone M4.) Only environments have secrets. Spaces
inside the braces are ignored; an unclosed `{{` stays as it is. If a name
occurs twice in one list, the later row wins. Values are inserted as they are – a `{{…}}` inside a value is not
resolved again. A placeholder without a value stops the request with an
error instead of sending it half resolved.

## Secrets

A variable with `secret = true` has no `value` in the environment file (one
written there by hand is ignored). Its value is stored encrypted with
[age](https://age-encryption.org/) in `secrets/<name>.age`, next to the
environment file `environments/<name>.toml` – the file stems match. Key
handling and the reasons: [ADR S4](../adr/s4-age-keys.md).

The `.age` file is ASCII-armored, so it can be committed. Decrypted, it is a
small TOML document:

```toml
format = "api-client/secrets"
version = 1

[values]
token = "…"
```

`.age-recipients` in the collection root lists who the secrets are encrypted
for, one public key per line (`age1…`, `ssh-ed25519 …`, `ssh-rsa …`); `#`
starts a comment. It is created with the user's own public key when the first
secret is saved. Secrets are re-encrypted for the current list whenever they
change, and all of them when the list is changed in the app; unchanged
secrets are not rewritten. When the app changes the list, comments and blank
lines stay, removed keys go and new keys are appended.
