# Collection file format, version 1

A collection is a folder of plain [TOML](https://toml.io) files, made to be
read, edited and merged in git. One file per request; folders of the
collection are real folders.

```
shop-api/                    ← collection root
  collection.toml            ← collection settings and order of the top level
  auth/                      ← a folder of the collection
    folder.toml              ← folder settings and order (optional)
    login.toml               ← a request
  products/
    folder.toml
    list-products.toml
    get-product.toml
```

## Common rules

- Encoding UTF-8, any line endings.
- Every file starts with `format` and `version`. A reader refuses a file
  whose `format` does not match its role.
- **Versions.** A reader migrates older versions in memory and writes the
  file only when the user saves it, so opening a collection never changes
  files. A file with a **newer** version than the program knows is shown
  read-only and never written.
- **Damaged files** (not valid TOML, wrong `format`, missing fields) are
  reported and left untouched; the rest of the collection still opens.
- **Comments and key order** in a file survive saving: only changed values
  are rewritten.
- **IDs** are UUIDs (version 7) stored in the file. They stay the same when a
  file is renamed or moved, so references (history, open tabs) survive.
- **Unknown keys** are kept when saving, so newer or other tools can add
  data without it getting lost.
- Names starting with `.`, and the folders `environments` and `secrets` in the
  collection root (used from milestone M3), are not part of the request tree.

## `collection.toml`

```toml
format = "api-client/collection"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a70"
name = "Shop API"
order = ["auth", "products"]
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the collection |
| `name` | string | Display name |
| `order` | array of strings, optional | File and folder names of the top level in display order |
| `variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`): variables for every request of the collection |
| `auth` | table, optional | Authentication for every request of the collection (see [Authentication](#authentication)); missing = none |
| `verify_tls` | boolean, optional | Check servers' TLS certificates (see [Certificate check](#certificate-check)); missing = `true` |
| `follow_redirects` | boolean, optional | Follow redirects for every request of the collection; missing = `true` |
| `timeout_seconds` | integer ≥ 1, optional | Time limit per request in seconds; missing = 30 |
| `cookies` | boolean, optional | Send and keep cookies for every request of the collection; missing = `true` |
| `scripts` | table, optional | Scripts around every request of the collection (see [Scripts](#scripts)) |

## `folder.toml`

```toml
format = "api-client/folder"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a71"
name = "Products"
order = ["list-products.toml", "get-product.toml"]
```

Same keys as `collection.toml` (including `variables`, `auth` and
`scripts`, which apply to the requests in the folder and its subfolders; a
missing `auth` inherits). The file is optional: without
it, the folder is named after its directory and gets an ID when it is first
saved.

**Order.** Entries listed in `order` come first, in that order; entries that
exist but are not listed (added by hand or by a git merge) follow,
sorted by name; listed entries that do not exist are skipped. Nothing is
hidden because of a stale `order`.

## Request files (`*.toml`)

Every other `.toml` file in the collection is a request.

```toml
format = "api-client/request"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a77"
name = "Get product"

[request]
method = "GET"
url = "{{baseUrl}}/products/42"

[[request.headers]]
name = "Accept"
value = "application/json"
enabled = true

[request.body]
type = "json"
content = '''
{ "name": "Teapot" }
'''
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the request |
| `name` | string | Display name |
| `request.method` | string | HTTP method (case-sensitive token, e.g. `GET`, `PROPFIND`) |
| `request.url` | string | URL; may contain `{{variables}}` (resolved from milestone M3) |
| `request.headers` | array of tables, optional | `name`, `value`, `enabled` (default `true`) |
| `request.body` | table, optional | The body (see [Bodies](#bodies)); missing = no body |
| `request.variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`): variables of this request only |
| `request.auth` | table, optional | Authentication of this request (see [Authentication](#authentication)); missing = inherit |
| `request.verify_tls` | boolean, optional | Check the server's TLS certificate (see [Certificate check](#certificate-check)); missing = inherit |
| `request.follow_redirects` | boolean, optional | Follow redirects (`false`: show the 3xx response); missing = inherit, followed by default |
| `request.timeout_seconds` | integer ≥ 1, optional | Time limit of the whole request in seconds; missing = inherit, 30 by default |
| `request.cookies` | boolean, optional | Send the collection's cookies and keep the ones received (`false`: neither); missing = inherit, on by default |
| `request.path_params` | array of tables, optional | `name`, `value`: values of the path variables in the URL (a segment `/:name` is replaced by the value when sending; the value may contain `{{variables}}`) |
| `request.disabled_query` | array of tables, optional | `name`, `value`: query parameters switched off in the params table – kept here, not sent. Switched-on query parameters are simply part of `request.url` |

Further body types (form, multipart, binary) and auth follow in milestone M5
as new keys; files without them stay valid.

**File names** are derived from the name when a request is created
(lower case, `-` instead of spaces, umlauts transliterated, unique in the
folder). Renaming a request later does not rename its file automatically.

## Bodies

```toml
[request.body]
type = "json"                   # json | text: `content` is the text
content = '{"name": "Teapot"}'

[request.body]
type = "form"                   # form | multipart: a list of fields
[[request.body.fields]]
name = "q"
value = "tea"
enabled = false                 # optional, default true
[[request.body.fields]]        # multipart only: a file instead of a value
name = "avatar"
file = "files/avatar.png"

[request.body]
type = "binary"                 # the contents of `file`, as they are
file = "data/payload.bin"
```

| `type` | Sent as | `Content-Type` (unless the request sets one) |
|---|---|---|
| `json` | `content` | `application/json` |
| `text` | `content` | `text/plain; charset=utf-8` |
| `form` | the enabled fields, URL-encoded | `application/x-www-form-urlencoded` |
| `multipart` | the enabled fields as form data; file fields with their file name | `multipart/form-data` with its boundary (always set by the program) |
| `binary` | the contents of `file` | `application/octet-stream` |

Texts, field names and values and file paths may contain `{{variables}}`.
**File paths** are relative to the collection folder unless absolute, so a
collection with its files works for everyone who checks it out. Files are
read when the request is sent; a missing file shows as a failed request.

## Environment files (`environments/*.toml`)

Every `.toml` file in the `environments` folder of the collection root is an
environment: a named set of variables for `{{name}}` placeholders.

```toml
format = "api-client/environment"
version = 1
id = "0193a8f2-7c1e-7b40-9d3a-5f2c8e1b4a80"
name = "Staging"

[[variables]]
name = "baseUrl"
value = "https://staging.example.com"

[[variables]]
name = "debug"
value = "1"
enabled = false

[[variables]]
name = "token"
secret = true
```

| Key | Type | Meaning |
|---|---|---|
| `id` | string (UUID) | Identity of the environment |
| `name` | string | Display name (default: file name) |
| `variables` | array of tables, optional | `name`, `value`, `enabled` (default `true`), `secret` (default `false`) |

**Placeholders.** Before a request is sent, every `{{name}}` in its URL,
header names and values and body is replaced by the value of the enabled
variable `name`. Variables can be defined in several places; from weakest
to strongest:

1. the collection (`collection.toml`),
2. the chosen environment,
3. the folders around the request (`folder.toml`), outer to inner,
4. the request itself (`request.variables`).

The stronger place wins. (Variables set by scripts at run time will rank
above all of them, milestone M4.) Only environments have secrets. Spaces
inside the braces are ignored; an unclosed `{{` stays as it is. If a name
occurs twice in one list, the later row wins. Values are inserted as they are – a `{{…}}` inside a value is not
resolved again. A placeholder without a value stops the request with an
error instead of sending it half resolved.

## Authentication

```toml
[request.auth]          # [auth] in collection.toml and folder.toml
type = "bearer"
token = "{{token}}"
```

| `type` | Further keys | Sent as |
|---|---|---|
| `none` | – | nothing (also stops inheriting) |
| `basic` | `username`, `password` | `Authorization: Basic base64(username:password)` |
| `bearer` | `token` | `Authorization: Bearer <token>` |
| `api-key` | `name`, `value`, `in` = `"header"` (default) or `"query"` | the header or query parameter `name` |
| `oauth2` | `grant` = `"client-credentials"` (default) or `"authorization-code"`, `token_url`, `client_id`, `client_secret` (may be empty for the authorization code), `scope` (optional, separated by spaces); for the authorization code also `auth_url` and optionally `redirect_url` | `Authorization: Bearer <token>` |
| `digest` | `username`, `password` | after the server's 401 challenge: `Authorization: Digest …` (MD5 or SHA-256, `qop=auth`) |
| `aws-sigv4` | `access_key_id`, `secret_access_key`, `region`, `service`, `session_token` (optional) | AWS Signature Version 4: `Authorization: AWS4-HMAC-SHA256 …`, `X-Amz-Date`, and `X-Amz-Security-Token` with a session token |

Without a table a request or folder **inherits**: the innermost folder around
it that has one decides, else the collection; without any, nothing is sent.
All values may contain `{{variables}}` – credentials belong in an
environment's secrets, not in plain text in a file (the app warns about plain
credentials). A header or query parameter of the same name that the request
sets itself takes precedence over the authentication.

With `oauth2` the app obtains an access token just before sending and keeps
it in memory until shortly before it expires; tokens are never written to
disk. A client with a secret authenticates at `token_url` with HTTP Basic, a
client without one names its `client_id` in the form.

- **Client credentials:** a form POST with `grant_type=client_credentials`.
  A token response without `expires_in` is used for one request only.
- **Authorization code** (RFC 8252, always with PKCE S256): on the first
  send the app opens `auth_url` in the browser and waits up to five minutes
  for the redirect to `redirect_url`, an `http` URL on the loopback address
  (`127.0.0.1`, `localhost` or `[::1]`); without one it listens on a free
  port at `http://127.0.0.1/callback`. The code is exchanged at
  `token_url`. A token without `expires_in` is kept until the app ends; a
  refresh token, if the server sends one, renews expired tokens without
  signing in again. The command `BROWSER` names, if set, is used instead of
  the system's browser.

## Certificate check

Servers' TLS certificates are checked. `verify_tls = false` switches the
check off – for test servers with self-signed certificates – in a request
(`[request]`), a folder (`folder.toml`) or the collection
(`collection.toml`); `verify_tls = true` switches it on again below. Without
the key a request or folder inherits, like [authentication](#authentication).
The app shows a clear warning on every request whose check is off.

## Scripts

```toml
[request.scripts]
pre_request = '''
req.setHeader("X-Request-Id", String(Date.now()));
'''
post_response = '''
env.set("token", res.json().token);
'''
```

TypeScript or JavaScript that runs before the request is sent and after its
response arrived ([scripting](../scripting.md)). Both keys are optional; no
table means no scripts. The app writes scripts as multi-line literal
strings, so they stay readable and diff well.

`collection.toml` and `folder.toml` have the same table as `[scripts]`
(without `request.`). These scripts run for every request in the
collection or folder: before sending from the outside in (collection,
outer folders, inner folders, the request's own), after the response in
reverse order.

## Secrets

A variable with `secret = true` has no `value` in the environment file (one
written there by hand is ignored). Its value is stored encrypted with
[age](https://age-encryption.org/) in `secrets/<name>.age`, next to the
environment file `environments/<name>.toml` – the file stems match. Key
handling and the reasons: [ADR S4](../adr/s4-age-keys.md).

The `.age` file is ASCII-armored, so it can be committed. Decrypted, it is a
small TOML document:

```toml
format = "api-client/secrets"
version = 1

[values]
token = "…"
```

`.age-recipients` in the collection root lists who the secrets are encrypted
for, one public key per line (`age1…`, `ssh-ed25519 …`, `ssh-rsa …`); `#`
starts a comment. It is created with the user's own public key when the first
secret is saved. Secrets are re-encrypted for the current list whenever they
change, and all of them when the list is changed in the app; unchanged
secrets are not rewritten. When the app changes the list, comments and blank
lines stay, removed keys go and new keys are appended.
